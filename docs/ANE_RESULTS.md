# Испытания Apple Neural Engine — 5 октября 2026

MacBook Pro M4 Pro, 24 ГБ, macOS 15.1; ONNX Runtime 1.30.0,
PaddleOCR 3.7.0. Детектор PP-OCRv5 server, распознаватель eslav mobile.

## Реализация

Детектор использует Core ML MLProgram FP16 со статическими размерами входа.
Распознаватель работает на ONNX CPU. Исходная ONNX-модель не изменяется.
В отдельной копии удалён избыточный ceil_mode у MaxPool со stride=1 и SAME:
на контрольном тензоре FP32 разница после этой правки была нулевой.
Затем объединяются BatchNorm и выполняется преобразование FP16.
FP16 уже меняет численные результаты и иногда рамки текста.

ProfileComputePlan показал для каждого из трёх размеров 262 операции
с MLNeuralEngineComputeDevice и 4 с MLCPUComputeDevice. Таким образом,
назначение на ANE подтверждено планом Core ML, а не только настройкой
CPUAndNeuralEngine. Измерения потребляемой мощности не проводились.
GPU в этом режиме не используется.

Повышен лимит контуров детектора с 1000 до 10000: на большом тёмном
синтетическом изображении прежний лимит обрезал строки. Порог детекции
не менялся. Предел стороны 4000 сохраняет разрешение тестовых изображений.

Это повторный проход каждого теста, не статистическая оценка множества запусков.

Импорт библиотек, первоначальная загрузка моделей, выделение экрана и работа
буфера обмена в эти времена OCR не включены.

## Точность

Четыре синтетических изображения Menlo с английским и русским кодом,
3024 эталонных символа после удаления пробелов по краям каждой строки.
Расстояние редактирования восстановленного текста: CPU — 106,
ANE — 100. На маленьком тесте оба результата точные; на остальных
сохранились ошибки кириллицы/латиницы, минусов и отдельных знаков.
Эта метрика не проверяет точность отступов и не гарантирует качество
на реальных скриншотах. Побуквенная идентичность CPU и ANE не обещается.

Восемь автоматических тестов прошли, включая JSON-протокол, повторное
использование модели и переход на CPU при ошибке компиляции/невалидном выходе.

## Воспроизведение

`scripts/benchmark_ocr.py` создаёт синтетические изображения и эталоны.
CPU: `--backend cpu --case all --max-candidates 10000 --repeat 2 --output cpu.json`.
Для ANE добавьте `--static-model /путь/к/FP16/inference.onnx`.
Получить копию можно через `scripts/prepare_coreml.py SOURCE DEST --fp16`.
Рабочий режим: `scripts/ocr_worker.py --accelerator auto`.
Переменная `OCR_COREML_PROFILE=1` включает печать плана устройств в stderr.

При отказе Core ML автоматически используется исходный ONNX CPU;
backend и длительность каждого запроса выводятся в консоль Hammerspoon.

Описание опций: [ONNX Runtime Core ML EP](https://onnxruntime.ai/docs/execution-providers/CoreML-ExecutionProvider.html).
