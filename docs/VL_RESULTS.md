# PaddleOCR-VL-1.6: экспериментальный режим

Установлен 5 октября 2026 на M4 Pro 24 ГБ, macOS 15.1.
Горячая клавиша **Ctrl + Option + Cmd + 5**. `… + 4` сохраняет быстрый PP-OCRv5.
VL запускается лениво и сохраняет модель в памяти до перезагрузки Hammerspoon.
Работает локально через MLX на Apple GPU. Этот режим не использует ANE.

## Проверка на скриншоте пользователя

798×704, русский текст и SQL с подсветкой. Сравнивался текст из сообщения
пользователя, без Markdown-разметки, с сохранением регистра и Unicode-символов.
Для символьного расстояния удалены все пробельные символы: переносы строк,
отступы и разделяющие пробелы этой метрикой **не оцениваются**.

| Режим | Правки Левенштейна / 1473 символа |
| --- | ---: |
| PP-OCRv5, текущий ANE + CPU | 132 (8,96%) |
| PP-OCRv5, увеличение изображения вдвое | 137 (9,30%) |
| Apple Vision, установленный бинарник | 15 (1,02%) |
| PaddleOCR-VL-1.6, стандартный `OCR:` | 11 (0,75%) |

VL обработал весь кадр за 3,8 с после загрузки модели, пиковая память MLX
около 3,0 ГБ. Один контрольный прогон, не медиана серии. Время загрузки
Python и весов сюда не входит. Типичные остаточные ошибки: `l` → `1`,
одно потерянное подчёркивание, опечатка в заголовке. SQL на полной странице
сливается в одну строку.

Отдельно выделенный первый SQL-блок: 0,9 с, без символьных ошибок при
исключении пробелов; переносы строк сохранены, ведущие отступы потеряны.
Поэтому при переносе кода предпочтительно выделять непосредственно код.
Это результат одного изображения, а не гарантия точности на других.

Проверены и отвергнуты для режима по умолчанию:

- расширенная инструкция о буквальном копировании — 13 ошибок;
- Spotting с координатами — 28 ошибок, 7,8 с;
- автоматическая нарезка по вертикальным пробелам — модель добавляла LaTeX
  вокруг обычных фрагментов текста, 59 ошибок.

Исходный скриншот и содержимое пользовательского SQL в репозиторий не добавлены.

## Установка

```bash
python3.12 -m venv ~/.hammerspoon/.venv-vl
~/.hammerspoon/.venv-vl/bin/python -m pip install -r scripts/requirements-vl.txt
~/.hammerspoon/.venv-vl/bin/python -c 'from huggingface_hub import snapshot_download; snapshot_download("PaddlePaddle/PaddleOCR-VL-1.6", revision="c5630abae1d940eafe0697512a0325494b02ab42", allow_patterns=["*.json", "*.safetensors", "*.py", "*.txt", "*.model", "*.jinja"])'
cp scripts/ocr_vl.py scripts/ocr_vl.lua ~/.hammerspoon/scripts/
cp init.lua ~/.hammerspoon/init.lua
```

Перезагрузить конфигурацию Hammerspoon. Веса BF16, без дополнительного
квантования. Версия весов зафиксирована; фоновый процесс открывает их
из локального кеша, без скачивания во время сканирования.

```bash
~/.hammerspoon/.venv-vl/bin/python ~/.hammerspoon/scripts/ocr_vl.py image.png
ps -axo pid,ppid,etime,command | rg '[o]cr_vl.py'
```

В консоли Hammerspoon выводятся backend и время. Ошибка, тайм-аут 180 с
или достижение лимита 8192 токенов не заменяют содержимое clipboard
частичным текстом. Модель может переформатировать текст даже без ошибок
протокола; результат нужно оценивать на ваших фрагментах.

Источники: [карточка модели](https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.6),
[интеграция MLX-VLM](https://github.com/Blaizzy/mlx-vlm/blob/main/mlx_vlm/models/paddleocr_vl/README.md).

## Сравнение VLM-кандидатов (5 октября 2026)

Тот же скриншот 798×704, MLX на GPU M4 Pro, temperature 0, второй (прогретый)
прогон. `×2` — изображение увеличено вдвое (LANCZOS) перед подачей в модель.
Скрипт: `scripts/benchmark_vlm.py`. Ошибки — расстояние Левенштейна на
1473 символа после удаления Markdown-обёрток (```` ``` ````, `**`, `` ` ``)
и, для chandra/Unlimited, HTML/`<|det|>`-тегов. «Без пробелов» — только
символы; «с отступами» — дополнительно переносы и ведущие отступы кода.

| chandra-ocr-2 8bit ×2 | 2 | **2** | 24,5 с | 6,9 ГБ |

DeepSeek-OCR-2 не загрузился: процессор несовместим с transformers 5.18.

Промпт для Qwen3.5 и chandra: «Transcribe all text in this image exactly as it
appears, preserving line breaks and code indentation. Output plain text only,
no Markdown, no commentary.» Qwen всё равно оборачивает код в ```` ``` ````
и теряет ведущие отступы; chandra игнорирует промпт и выдаёт HTML с bbox,
зато сохраняет отступы. Оставшиеся ошибки лидеров: `~` → `-`,
`__` → `_`, латинские буквы → похожие кириллические.

Время почти целиком — генерация (~500 токенов), поэтому пропорционально
объёму текста: выделение только кода ускоряет распознавание в разы.
Один скриншот, один прогон на точку — это ориентир, а не гарантия.
Лицензия весов chandra-ocr-2 (modified OpenRAIL-M) ограничивает коммерческое
использование организациями с выручкой/финансированием выше $2M.
