# Выбор OCR для скриншотов VDI

Цель проекта — переносить обычный текст и исходный код с экрана в локальный буфер. Для кода важны точные символы, пробелы, отступы и переносы строк. Удобочитаемый текст с исправленной пунктуацией здесь хуже буквального распознавания.

## Что было не так в текущем тракте

Apple Vision уже работал в режиме `.accurate` и с отключённой языковой коррекцией. Однако обработка после OCR заменяла типографские кавычки, `•#`/`·#` и удаляла завершающий `|`. Она также округляла отступы до уровней по четыре пробела и принудительно вставляла пробел между соседними фрагментами. Эти изменения могли портить корректно распознанный код. Они удалены; пробелы между отдельными OCR-блоками теперь оцениваются по реальному промежутку между их рамками.

## Скорость на этом Mac

Разовый запуск `ocr_paddle.py` тратит время на импорт Python-библиотек и загрузку моделей при каждом снимке. Фоновый процесс запускается при загрузке Hammerspoon, поэтому после прогрева горячая клавиша оплачивает только время снимка и распознавания.

В установленной версии детектор преобразуется в FP16 MLProgram со статическими размерами. Назначение на ANE подтверждено профилем Core ML: 262 операции на Neural Engine и 4 на CPU для каждого проверенного размера. На больших синтетических кадрах повторный полный OCR занял 0,7–0,8 с против 2,6–4,1 с на ONNX CPU. Предел стороны — 4000 пикселей. Первый новый размер требует компиляции: в финальной проверке до 4,5 с. Подробности и ограничения точности — в [отчёте испытаний](ANE_RESULTS.md).

Проверить нагрузку Neural Engine во время серии сканирований можно системной утилитой (она запросит пароль администратора):

```bash
sudo powermetrics --samplers ane_power -i 500 -n 20
```

## Как измерить точность

1. Сохранить 20–30 типичных изображений: код с отступами 2/4 пробела, табы, скобки, кавычки, `|`, смешанный русский/английский и мелкий шрифт. Для каждого сохранить вручную проверенный ожидаемый текст.
2. Запустить оба движка на **тех же PNG**, не меняя масштаб. Для каждого изображения сравнить результат с эталоном через символьное расстояние редактирования (CER), а также посчитать строки с любым отличием.
3. Отдельно отметить ошибки в синтаксисе и структуре: потерянные строки, изменённые отступы, добавленные/удалённые пробелы, путаницу `0/O`, `1/l/I`, кавычек и скобок. OCR, у которого меньше CER, но больше сломанного кода, не должен выигрывать.
4. Проверить скорость первого и повторных запусков на вашем Mac. Первый запуск PaddleOCR может скачать модель; это не часть времени собственно распознавания.

В этом репозитории нет ваших эталонных скриншотов, поэтому заявлять численное преимущество какого-либо движка было бы необоснованно. Автоматическое объединение результатов двух движков также не добавлено: без эталона оно может выбрать неверный символ.

## Источники API

- [PaddleOCR: установка и Python API](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/OCR.html) — `PaddleOCR`, `predict`, `rec_texts`, `rec_boxes`, `ocr_version` и `lang`.
- [PaddlePaddle: установка на macOS](https://www.paddlepaddle.org.cn/documentation/docs/en/install/pip/macos-pip_en.html) — поддерживаемые версии Python, ARM64 и CPU.
- [Hammerspoon: keyboard events](https://www.hammerspoon.org/docs/hs.eventtap.html) — параметр `keyStroke` задаёт длительность нажатия в микросекундах; `checkKeyboardModifiers` показывает удерживаемые модификаторы.
